В ходе принятия решений и выбора технологий приходилось руководствоваться описанием целевого процесса взаимодействия пользователя
с сайтом и интернет банком, а так же описанием процесса взаимодействия сотрудников колл-центра и бэк-офиса. Исходя из требований бизнеса,
необходимо наладить процесс создания и обработки заявок для клиента, а также сделать функционал для возможности сотрудников бэк-офиса не использовать
Excel документы, а работать с заявками по депозитам напрямую в АБС. Важно учесть, что система АБС сильно нагружена, поэтому в систему АБС должна
попадать уже готовая для обработки сотрудником бэк-офиса заявка. Для этого рассматривается ограничение не использовать Api вызовы для АБС,
а использовать систему очередей сообщений Kafka, чтобы АБС справлялся с созданием заявок в своей системе по мере его возможностей. Так же
немало важно то, что интернет-банк работает на устаревших технологиях и не поддерживает интеграцию с Kafka. Эта проблема решается вынесением
функционала депозитов интернет-банка в отдельный микросервис, где мы можем использовать новые технологии с поддержкой Kafka, но важно учитывать
еще то, что команда должна работать с теми технологиями, которые уже используются командой, значит мы можем просто поднять версию используемых платформ.
Тем самым мы сможем отдельно масштабировать микросервис, выполняя нефункциональные требования по надёжности и производительности.
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

Альтернативным решением может являться отказ использования системы очередей сообщений. Важно учесть, что одно из нефункциональных требований
это избегание прямой работы интернет-банка с Api АБС. В таком случае данные о заявках можно сначала накапливать в базе данных интернет-банка,
а затем загружать напрямую в базу данных системы АБС, избежав при этом большого количества запросов в бд АБС.

**Недостатки, ограничения, риски**

Подробно опишите здесь недостатки, ограничения и риски выбранного решения.

Недостатком может являться то, что данные в систему АБС могут попадать не сразу. Так же возможен риск, что большой запрос на вставку данных
о заявках может нагрузить базу данных системы АБС, что может повлиять на ее производительность. Так же, если в системе появятся еще сущности,
которые нужно будет отправлять в АБС, то с таким решением будет трудно собирать данные для дальнейшей их передачи в АБС, так как нужно постоянно
определять место и функционал, где их нужно накапливать.
